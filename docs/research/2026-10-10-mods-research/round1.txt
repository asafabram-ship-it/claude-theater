  [verdictForOurCase] WHAT THE DOCUMENTATION POINTS TO. The only element whose instance the engine promises to keep across the plugin's redraws is `Client`: "The engine keeps the instance (its local state, its timers) across the plugin's redraws while a `Client` under this key stays in the tree." (T:1494-1495); its state is "Kept across the plugin's redraws; dropped with the instance." (T:1548); new data reaches it either on a redraw ("a new value on a redraw reaches the running instance, its state kept", T:1509-1510) or with no ui.render at all through a `ui.message` answered `{ props }` ("hands the posting instance its next props directly, its local state kept, with no `ui.render` run", T:13946-13948); it has its own frame clock (`surface.every`, T:1568-1574) and `setState` that "schedules one more call of the function on the next frame; several calls before it coalesce into one redraw" (T:1552-1553) ‚Äî region-local, never a pane redraw; and it receives pointer input directly, with capture ("After a `down` in the region the instance holds the pointer until the `up`", T:1436-1438), so a click cannot be swallowed by a rebuild of the pane tree. `Svg` has none of this: it is a leaf whose markup is data, drawn "as an image, or in a sandboxed frame when `isInteractive`" (T:12199-12201), unclickable, and nothing in the docs says a frame is reused across a ui.render re-run; both of our triggers are documented redraws (any $.state write a reader saw: T:3374-3375, and every scroll step: T:4017-4018 / T:11784), so with 5-100 interactive Svg frames the blink is the documented architecture, not a bug we can configure away. So yes: for "animated tiles that survive the plugin's redraws and take clicks", the API's answer is one `Client` region (one per pane, or one per room keyed `room:<sessionId>`), with the hooks module feeding it plain props and the module animating on `surface.every`.

A Client cannot draw `Svg`: its table is "the terminal's (Elements) less `Client` ..., `Raster` and `Image`" (T:1391-1399) = Box/Text/Button/Input/Select/Link/Code/Markdown, laid out in character cells of the desktop's code font (T:10318-10324).
