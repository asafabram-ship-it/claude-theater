# Office pane as framed cards — design (2026-10-19)

Status: approved by Asaf live (cards probe round 4: "עכשיו זה נראה אחלה"; rounds 5-7 refined it the same day — the reference file is round 7). Replaces the cell-grid drawing of the agent rows (Tasks 2.8a/2.8b). Branch `feat/desktop-mod`.

## Why (root cause of "messy" after four rounds)
The office Client drew every row as cells padded with spaces, assuming every glyph is one cell of a monospace font. The desktop draws Text in a proportional UI font, so the columns never lined up. A probe with fixed cell widths (round 2-3) aligned the columns but CLIPPED the text: the desktop draws its letters wider than the cell metric (`Sonnet` → `nnet`, `חושב` cut vertically). Round 4 — column-major layout, each field a vertical Box sized by its widest value — aligned, unclipped, and approved.

## Reference
`docs/research/2026-10-19-cards-probe/register.tsx` is the approved drawing (round 7). Copy its structure and styling; the strings in it (e.g. `${emoji} ${name}`, `🤔 חושב`, toolbar `שסיימו ☐`) were seen correct on the desktop as written — do not re-derive their order with the old LTR-paragraph model (screenshots show the desktop lays a Hebrew-first Text right-to-left).

## Responsive behaviour and polish (probe rounds 8-9, approved by Asaf 19.10: "זה אחלה") — overrides the sections below where they differ
The reference file `docs/research/2026-10-19-cards-probe/register.tsx` is now round 9; its header comment and code are the spec for width behaviour. In short:
- One reading column at every width: up to 99 cells it is the pane; from 100 it is frozen at 100 and centred.
- The card's shape never changes with width (frame, title, a BLANK line where the rule was, rows, more line); widening/narrowing changes words and columns, never a line's position.
- ONE table mode for the whole office (from the widest values across all drawn rooms) with 2-cell hysteresis: below ~38 no model column and the activity as its emoji only; the model column back from ~39 (narrowing) / 42 (widening); the activity word from ~51/54; the model version from 60; toolbar + search on one line from 64; padding 2 and columns aligned across cards (minWidth floors) from 80; a dim task column from 100.
- Header/toolbar label ladder by LINE_FIT: full meter → header words → toolbar words → short/tiny meter; the meter is never cut.
- Counts show non-zero statuses only and shrink (✅ goes, then ⏳) before the title is cut below TITLE_MIN.
- Weight, not colour: working = bold name; waiting = regular name, dim activity; finished = all dim; ❌ keeps a regular name. ⭐ and ❌ rows rank first among the finished shown and are never hidden behind the more line.
- **No rule under the title** (round 9): it never stretched with the card. Title emphasis = bold + the blank line.
- **One-line texts never wrap** (round 9): spaces in titles, names and the more line become no-break spaces (U+00A0), so a text a little too long is clipped by its height-1 Box instead of breaking onto a second line; titles are cut by LINE_FIT.
- Search field only when more than 12 agents are shown (spec 2026-10-10 §2 item 22); an active search stays visible.
- The drawer: one dim status line (`● עובד · זמן 12 דק׳ · general-purpose`) and a blank line between identity and content.

### Live check 5 (Asaf, 20.10, a Hebrew pane of ~40 columns) — overrides the bullets above where they differ
- **The demo is obvious:** while it runs, the first line under the header reads `🎬 זו הדגמה - הסוכנים לא אמיתיים` (EN `🎬 Demo - these agents are not real`; amber), with an exit Button (`יציאה` / `Exit demo`) at the other edge; shorter notes when the pane is narrow (`🎬 הדגמה - לא אמיתיים`, `🎬 זו הדגמה`). The chrome is a row taller while it runs. A real subagent starting in the current conversation turns the demo off.
- **The demo obeys "show finished"** and the rooms' toggles like the real office (it no longer forces them on).
- **The finish toast** lasts 1.5 s, names the conversation (`✅ <persona> סיים · <room title>`, the title cut to ~30 cells on a word) and never fires for the demo's agents; which finishes toast is unchanged.
- **Title cut:** on a word only while the whole words keep two thirds of the room; else inside the word, with `…`. A Latin-dominant title is cut by FIT (bold Latin draws wider per cell than the text LINE_FIT was calibrated on); a Hebrew one by LINE_FIT.
- **No line break inside a one-line value:** besides the spaces, a hyphen or a dash becomes U+2011 (no-break hyphen), a slash before a letter U+2215 (division slash), a zero-width space and a soft hyphen are removed; a hyphen or slash before a digit is kept (no break there, and the number keeps its bidi run). Asaf's screenshot: `Plan the static-registry …` had broken at its hyphen onto two clipped lines.

### Live check 7 (Asaf, 21.10, the demo at ~50 columns: "the buttons are not smooth") — overrides everything above and below where they differ
Asaf's four complaints (slow; sometimes no response or the wrong action; the office jumps under the pointer; unclear what is clickable) traced to three families: a click changed the geometry under the pointer, every visible change waited for the whole remote round trip, and the in-card controls were plain dim text whose hit areas did not match what was drawn. Decision 24 of the client-office spec records Asaf's answers (Q1-Q10). Phase A (done, `desktop-mod/hooks/office-buttons.test.ts` drives each on the mount):
- **Search by the office's agents (Q1):** the field is drawn while the office holds more than 12 agents (its header counts), whatever the finished toggles show, or while a search is active. A click never adds or removes it, so the cards and the header's label ladder stay put.
- **Finished agents (Q3, Q6):** the toolbar's `הצג שסיימו ☐/☑` sets every card (its press clears every per-room override). The title's counts are read-only. Each card has ONE finished line, `עוד N שסיימו ◂` / `הסתר שסיימו ▾` (read arrow first: laid through iconLabel like every labelled control, so the arrow sits at the line's right edge, the Hebrew reader's start, and never moves as the label's width changes; `◂` is `▸`'s RTL form, pointing the reader's way — to show Asaf at the live check, decision 24 names ▸; English `▸ N more finished`), directly under its title (above the rows, so it never moves), drawn only when the room holds more than RECENT_DONE (3) finished; its arrow follows its state.
- **What is clickable (Q7):** the finished line is drawn in a theme link colour at rest (`suggestion`; never dim, bold or on a background). A row's and the line's hit is the card's inside (the border cell beside them is nothing). The dim 📌 shows over the pin's own zone alone, never the whole title line. The drawer's and the settings' close Buttons are alike (`role: 'dismiss'`, `סגירה ✕`, x; a close, never a flip).
- **Pin (Q4):** the bright 📌 shows at once; the card moves to the top only when the pointer leaves the office (the module keeps the drawn order until then), so a second click on the same cell is the same pin. The click keeps the hover on the clicked room, so its 📌 is drawn dim until the answer brings the bright one (dim and bright are one width: pinning and unpinning never slide the title).
- **The drawer (Q2, phase A):** one height per width (its lines padded to the most it takes there), so browsing agents or an agent finishing never moves the cards — except on a pane too short for that whole drawer to ride the window's top (20 body rows or fewer from 34 columns), where it is padded only to what still leaves the window a row, so a drawer opened while scrolled is drawn in view (a drawer longer than that keeps its lines; the floating overlay of phase B lifts this); a second click on the open agent closes it; the settings Button closes an open drawer, and closing the settings brings no old drawer back.
- **The demo (Q5, Q10):** drawn from the cast the poll published (a click's redraw no longer walks the newcomer in); the newcomer walks in as the last of its room's working rows. (Q10 departs from the recommendation, "at the end of its card, so no row moves": the props always draw the working rows before the finished ones, the probe's order, so the room's finished rows and every card below still move a line at each walk-in and walk-out. To put to Asaf at the live check — decision 24.) Leaving the demo draws at once the office as it was before it (the last real payload, kept in the hooks' memory), refreshed when the scan lands; the demo's switches post their target (`{ t: 'demo', on }`), so a double press of the exit leaves it off.
- **The motion toggle is gone (Q9):** its settings Button, the `s` key and the help row; the settings hold the demo and the language Buttons. The stored prefs keep their `still` field.
- **Speed and lost clicks:** the `ui.message` hook answers `{ props }` built by the render's own builder from what it just wrote (the press is drawn without waiting for the redraw; the redraw follows with equal props and the new height); the render's reads run in one round; a room's finished toggle is drawn at once (no 100 ms latch); `open` writes the selection first. Every post is a numbered batch of the frame's actions (one post per frame: a second click in the same frame once dropped the first), each applied once — the number checked at each action, as two posts' hooks run at once. Only the newest answer is drawn: a hook that a later post or a render overtook answers nothing (its reads see the moment it began, so its props would draw over the newer state and stick), and the redraw its own write asks for draws its change.
- **Smaller fixes:** the status column has a floor at every width (the focus marker never nudges the columns); a stale scroll offset (after a click that shortened the office) is clamped to the content, and stays clamped over the redraws that follow with it (the click's own focus, a hover, the next `{ props }` answer) until the engine hands an offset of the content; cards are keyed by their room; the language switch retitles before it writes; an Enter that follows typing in the search is the field's and never opens a drawer (o and Enter still open the focus, §6.4); the toolbar's and the settings' words or icons are decided on their toggles' widest state.
- **Waiting for a paint probe on the desktop (phase B):** the drawer and the settings FLOATING over the office's top (`position: 'absolute'`; nothing below moves at all), the hover underline on rows, the finished line and the toolbar Buttons, and the hover 📌 that does not shift the title (Q8). The R13 OVERSCAN waits for the floating overlay too: drawing and hit-testing every line while the office has at most WINDOW_ROWS lines (else bodyRows extra lines on each side of the window), so a stale offset never leaves blank or dead rows even before the clamp — while the drawer or the settings ride the window's top, the lines above the window cannot be drawn ahead of them without splitting the cut card in two (THE OVERLAY IN VIEW's fragment), and the floating overlay removes the fragment. Also measured live then: the click-to-paint time per hop; whether the desktop repaints on equal props; whether a button-less pointer `leave` reaches the Client (the pinned card goes to the top when the pointer leaves the office — if it never arrives, ask Asaf about a fallback, e.g. releasing the order on the next publish); and, widened to ≥ 62 columns, that one press of `f` flips the toggle once (the Button's hotkey and `onKey` in one frame both reach THE OUTBOX now — if it double-flips, drop the hotkeyed letters from the module's key map while hotkeys are on: R14).

## Refinements from rounds 5-7 (Asaf, 19.10) — these override anything below
1. **No selection background** (the dark band is gone). The open drawer shows which agent is selected; keyboard focus may show a small `›` marker beside the dot, nothing more.
2. **Every column is rigid and content-sized** (`flexShrink 0`): a shrinking activity column collapsed to nothing on the desktop. If the table cannot fit the pane, drop the activity WORD (keep its emoji) below a width threshold the implementer derives conservatively (the desktop draws letters wider than a cell; round 6 fit at 51 columns with 4 columns), never clip.
3. **Card title on one line:** a height-1 Box with `overflow hidden`, the title cut on a word with `…` by a conservative estimate (`max(8, floor((columns − 18) × 0.7))` characters in the probe), the counts never wrap (`flexShrink 0`).
4. **Cell padding on the reading side only** (`paddingLeft 1` in RTL), so the columns sit closer.
5. **NO time column** in the rows (reverses decision 16 for the desktop office): how long an agent has worked is in the drawer only (`זמן N דק׳` / `משך N דק׳`).
6. **Badges ride the status column** instead of the dot: ⭐ during the just-finished window, ❌ failed, ⏰ long-running; otherwise ● green running / ● amber stale / ○ grey done.
7. **Toolbar names:** `הצג שסיימו ☐` (☑ when on; EN `Show finished`), `צליל 🔔` (🔕), and `הגדרות ⚙️` (EN `Settings`) replacing `עזרה ?`. The popover it opens is titled `הגדרות` and holds language, demo, motion and the keyboard shortcuts.

## Drawing (desktop office Client only; terminal/vscode/mobile text cards unchanged)
- Header line: `🎭 עובדים N · ממתינים N · סיימו N` (bold) at the reading edge, the 5h meter dim at the other edge.
- Toolbar: the three labelled Buttons (`שסיימו ☐`, `צליל 🔔`, `עזרה ?`), gap 2. Search below with a blank line above and below.
- Each room = a card: `Box borderStyle="round" borderColor="#56607a" paddingX={1} paddingY={1} marginBottom={1} width="100%"`:
  - title line (bold title at the reading edge, dim counts at the other edge, 📌 when pinned / dim 📌 on hover at the reading edge, the counts are the roomDone toggle);
  - a dim rule `─…` under it;
  - the agent table, COLUMN-MAJOR: `Box flexDirection=row-reverse (RTL) | row (LTR)` of five column Boxes (`flexDirection=column`, aligned to the reading edge, `flexShrink 0` except the activity column `flexGrow 1, flexShrink 1, overflow hidden`): status dot (● green running / ● amber stale / ○ grey done), `emoji name` (bold; dim when done), model word (dim), activity (`🤔 חושב`, done = `✅ סיים`, dim), time (`⏱️ 3′` for working agents, empty for done) + badges (⭐ ❌ ⏰). Every value one line: each value sits in a `Box height={1} paddingX={1} width="100%"` so no wrap can change a row's height.
  - the `▸ עוד N שסיימו` / `▸ הסתר שסיימו` line (marginTop 1).
- Selected agent: the row's cell Boxes get `backgroundColor #2a3150` in every column; hover a lighter tint; the finish pulse a subtle tint + ⭐.
- No colours on names/models/activities beyond dim/bold; colour only on the status dot.
- Drawer and help keep their content; the drawer drawn as a card in the same style.

## Interaction (unchanged behaviour)
Row click → drawer; pin, roomDone counts, more/hide row, toolbar, help buttons, search, keys j/k/o/x/f/m/h/d/s/l — all as in `office-controls.test.ts`. Hit-testing: the Client knows the y of every line (card top border, padding, title, rule, rows, more, bottom padding/border, gap); every line is height 1 by construction, so pointer y maps to a line; x is irrelevant for rows (whole row), the title line keeps the pin/counts zones.

## Constraints
No flicker (no change to register.tsx publish logic or the Client update path); props JSON < 100k chars; the drawn tree within the engine's limits at 200 agents and a 200×80 pane (window by whole cards or by lines, the implementer decides, tested); both engines 2.1.293 / 2.1.295; tsc clean. The cell-grid helpers no longer used by the Client are removed with their tests; keep what props/text cards still use (`cut`, `glyphs`, `textWidth`).
